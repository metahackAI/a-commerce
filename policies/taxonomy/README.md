# 상품 분류와 속성 (초안)

[README](../../README.md) › [policies](../README.md)

여러 상품군(의류, 전자기기, 식품)의 분류 트리와 속성 사전입니다. 쇼퍼의 말을 닫힌 필터로 바꾸고, 판매자가 BO에서 같은 모양으로 상품을 넣고, schema.org와 피드로 그대로 내보내기 위한 것입니다. 설계와 이유는 [../../docs/catalog-taxonomy.md](../../docs/catalog-taxonomy.md)에 있습니다.

> **초안입니다.** 아직 어떤 코드도 이 폴더를 읽지 않습니다. `acom-policy`의 `FILES`에도 들어 있지 않습니다. 리뷰로 모양을 정한 뒤 로더와 검사를 만듭니다. "확인 필요"라고 적힌 값은 원문이나 표준을 다시 확인해야 합니다.

## 파일

| 파일 | 내용 |
|---|---|
| [common.yml](common.yml) | 값의 종류, 표준 단위(UN/CEFACT 코드), 모든 상품군이 쓰는 속성(색 계열, 소재, 무게, 크기, 원산지, 인증, 성별, 연령), 결과 0개일 때 푸는 순서 |
| [colors.yml](colors.yml) | 색 이름 사전: 이름마다 색 계열(1~3개)과 견본 색(hex). 검색은 계열로, 화면 칩과 사진 프롬프트는 견본 색으로 |
| [apparel.yml](apparel.yml) | 의류·신발·잡화 속성: 핏, 보온, 두께감, 신축성, 비침, 촉감, 원단, 안감, 용도, 계절, 방수, 기능, 세탁, 섬유 조성, 발길이, 굽 높이 |
| [electronics.yml](electronics.yml) | 전자기기 속성: 화면, 해상도, 저장 용량, 메모리, 배터리, 출력, 연결, 단자, 충전 규격, 호환 기기, 노이즈 캔슬링 |
| [food.yml](food.yml) | 식품 속성: 내용량과 단위가격, 원재료, 알레르기(3상태), 식단, 무첨가, 영양성분, 영양 강조, 보관, 맵기, 맛 |
| [nodes.yml](nodes.yml) | 분류 트리: 노드마다 필수·선택 속성, 옵션 축, 품목, KC 대상 여부, 고시 상품군, Google 분류 경로 |
| [notice.yml](notice.yml) | 상품정보제공고시 상품군별 템플릿: 항목마다 어느 속성이나 스토어 설정에서 오는지 |

## 규칙

- 속성은 한 번만 정의하고 노드가 골라 씁니다. 자식 노드는 부모의 속성을 물려받습니다.
- 값 목록은 20개 안팎으로 짧게 둡니다. 긴 꼬리 낱말은 `words`에 둡니다.
- 정의는 영어 하나로 씁니다(코드, 이름표, `means`, `words`). 다른 언어로 물으면 질의 쪽(에이전트, 질의 이해 단계)이 영어 코드로 바꿉니다. 다른 언어 화면이 필요해지면 언어별 번역 파일을 따로 둡니다. 예외는 한국 법의 문구인 [notice.yml](notice.yml)입니다.
- 정도가 있는 속성은 `scale`(순서 있는 단어), 사양은 `number`(표준 단위 하나)로 둡니다.
- 값이 비어 있으면 "모름"입니다. "없음" 필터에 걸리지 않습니다(`unknown_is_not_none`).
- 법이나 안전에 걸린 값은 `requires_evidence`로 근거(인증 기록)를 요구합니다.
- 값의 뜻을 바꾸지 않습니다. 값을 없앨 때는 지우지 않고 `replaced_by`로 폐기합니다.
